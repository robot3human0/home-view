# HomeView — Linux-клиент

## Контекст

- HomeView — «social desktop pet» для macOS от iOS-команды: прозрачный оверлей поверх всех окон,
  сезонные осадки (снег/лепестки/пух/листья), бригада рабочих, человечки коллег по офисной сети, мини-игры.
  Распространяется архивом, своего git-репозитория у авторов нет.
- Наша команда — backend на C++, Ubuntu, **X11** (NVIDIA, Wayland не используем). Команда русскоязычная.
- Цель: Linux-клиент, подключающийся к **тому же серверу** на Mac mini, чтобы мы и маководы видели друг друга.
- Стек: **Python 3 + PySide6** (прототип). Возможен поздний перенос на C++/Qt 6 — держать архитектуру
  близкой к Qt-идиомам, без экзотических Python-библиотек.
- UI на **русском**. Документация авторов — на узбекском.

## Структура репозитория

- `main` — оригинал HomeView 1.0.0 из архива, **не изменять**. Новые версии от iOS-команды класть
  отдельным коммитом в `main`, затем мержить в `linux-client` и смотреть diff `HomeViewProtocol/`.
- `linux-client` — рабочая ветка. Весь наш код в `HomeViewLinux/`.
- Папки `HomeView/`, `HomeViewServer/`, `HomeViewProtocol/`, `tools/` — чужие, не правим.
- Спрайты берём из `HomeView/Art/*.png` по относительному пути, не копируем.

## Протокол (источник правды: `HomeViewProtocol/Sources/HomeViewProtocol/Protocol.swift`)

- Транспорт: WebSocket, **текстовые** кадры, JSON. Порт `47777` (страница загрузок — `47778`).
- Обнаружение: mDNS/Bonjour `_homeview._tcp`; запасной вариант — адрес вручную (`host[:port]`, URL `ws://host:port/`).
- Версия протокола: `4`. Сервер отклоняет `hello` с `version < 4`, неверным офисным кодом или пустым именем
  (`{"rejected":{"reason":...}}`).
- Формат Swift `Codable` для enum с ассоциированными значениями:
  - именованные поля: `{"hello":{"id":"…","name":"…",…}}`
  - безымянное значение: `{"status":{"_0":"active"}}`, `{"peerJoined":{"_0":{PeerInfo}}}`
  - без значений: `{"jump":{}}`
  - `Optional` = nil — ключ отсутствует (Swift не пишет `null` по умолчанию).
- Первое сообщение клиента: `hello(id, name, team, avatar, status, code, version)`; ответ `welcome(you, peers, rooms)`.
- Цвета в `AvatarStyle` — `UInt32` 0xRRGGBB. `HatStyle`: `beanie | cap | doppi | strawHat`.
  `PeerStatus`: `active | away | busy | hidden`.
- Mac-клиент переподключается с задержкой 2→4→8…30 с.

## Рендер (как в Mac-версии)

- Оверлей на каждый монитор, уровень над обычными окнами, клики проходят насквозь (в режиме игры — перехват).
- Спрайты PNG нарисованы с плотностью **8 px на точку** (`ArtPack.pixelsPerPoint`).
- Перекраска: серый PNG × цвет (multiply), альфа исходника сохраняется.
- Человечек (`Art.realisticWorkerParts`, `PeerAvatar.buildFigure`), координаты в точках, Y вверх, (0,0) — ступни:
  - нога `hv_person_leg`, box (-2.6, -11.2, 6.4×11.4), pivot-ы в (-2.6, 11) и (2.6, 11)
  - руки `hv_person_sleeve`(+`hv_person_hand` в цвет кожи), box (-2.4, -12.4, 4.8×12.6),
    задняя в (-4, 22) цветом куртки ×0.85, передняя в (3, 22), поворот 0.15 рад
  - тело box (-9.8, 9.6, 20.6×33.4): `torso`(куртка) + `jacket` + `head`(кожа) + `face` + шапка
  - шапки: beanie = `hv_hat_beanie`(цвет) + `hv_hat_beanie_pom`; cap = `hv_hat_cap`(цвет);
    doppi = `hv_hat_doppi`; strawHat = `hv_hat_straw` + `hv_hat_straw_band`(цвет)
  - порядок слоёв: левая нога, правая нога, задняя рука, тело, передняя рука
  - статус away — сидит (ноги 1.35/1.2 рад, фигура −8 по Y); busy — прозрачность 0.55
  - табличка с именем: «Имя · Команда», над головой (+46·scale +10)
- Сезон по месяцу: 12–2 зима, 3–5 весна, 6–8 лето, 9–11 осень. Частицы — 3 слоя (far/mid/near),
  параметры в `Season.swift` (rate, velocity, scale, alpha, spin, emissionRange).

## Отрисовка и видеокарта (выяснено опытом)

- По умолчанию рисуем через **OpenGL** (`QOpenGLWindow` + `QPainter`), осадки — **целиком в шейдере**
  (`gl_particles.py`: точки-спрайты, положение считается от времени). CPU ≈ 10% ядра.
  Программный вариант (`RasterOverlayWindow`, частицы на Python) — запасной, ≈ 57% ядра + нагрузка на композитор.
- Выбор карты — `gpu.py`, ДО создания `QApplication` (переменные окружения читаются при загрузке libGL),
  смена режима = перезапуск процесса (`HomeViewApp.restart`, `os.execve`).
- **Грабли:** переменные PRIME offload (`__NV_PRIME_RENDER_OFFLOAD`, `__GLX_VENDOR_LIBRARY_NAME=nvidia`)
  при X-сервере, уже работающем на NVIDIA, дают GLX-конфиг **без альфа-канала** → окно Depth 24 →
  **чёрный экран вместо прозрачного**. Поэтому сначала пробуем без переменных, проба требует alpha ≥ 8,
  а после создания окна `has_alpha` проверяется ещё раз (иначе — откат на программную отрисовку).
- **Грабли:** в PySide6 биндинг `QPainter.drawPixmapFragments` принимает только один фрагмент — пакетной
  отрисовки через него нет.
- Qt ≥ 6.5 под X11 требует системный пакет `libxcb-cursor0` (иначе тихо падает при старте).
- Машина разработчика и мониторы — в `CLAUDE.local.md`.

## Тестирование

Сервера (Mac mini) локально нет — для проверки `HomeViewLinux/tools/mock_server.py` (боты-коллеги, строгая
проверка формата сообщений). Тестовые запуски — с `XDG_CONFIG_HOME` во временной папке, чтобы не трогать
настройки пользователя.

**Перед полноэкранным запуском оверлея** проверять прозрачность: на маленьком тестовом окне или
`xwininfo -id <win> | grep Depth` сразу после старта (должно быть 32; иначе немедленно убить процесс).
Полноэкранный тест появляется на экране пользователя — предупреждать заранее.

Отрисовку без окон можно проверять offscreen: `World` → `QImage` → PNG.

**Совместимость с протоколом** проверяется настоящим Swift: `HomeViewLinux/tools/swift_check/run.sh`
(Docker-образ `swift:6.0-noble` у пользователя уже скачан и оставлен специально). Проверено 2026-11-20:
19/19 сообщений клиента и 16/16 сообщений сервера. Swift принимает `"to": null` так же, как отсутствие ключа.
